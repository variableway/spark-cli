# 踩坑记录

每一条都是真踩过的，写清楚**症状**和**为什么**，方便下一个人直接对号入座。

## 1. 素材里的字被卡片边缘切掉，体检量不到

**症状**：画面上少半个词，看着像工具输出本身就这样。

**原因**：终端素材是**图片**。体检只量 `textBlock` 画的字，看不见图片里的字被裁掉了。
一行 72 列的文字裁到 58 列，右边那截就没了。

**对策**：`check_crop.py` 按真实命令输出的行宽逐行核对。列数要 ≥ 裁剪范围内最宽的一行。
竖版尤其容易踩——横版塞得下 92 列，竖版只塞得下 58 列，多一行就得换素材或缩内容。

## 2. 名义列宽不等于真实列宽（差 3%）

**症状**：标注线比文字长出一截；或者终端里的字看着被横向拉宽了。

**原因**：素材是「超采样 → 缩到目标宽」渲染的，文本区**两侧留了内边距**。
1250px 宽的素材里，文字只占 1212.6px（92 列 × 13.18px）。
所以「画幅宽 ÷ 列数」= 13.587 是名义值，真实列宽是 13.180，差 3.09%。
用名义值算出的裁剪框宽 1268.7px，超出了 1250px 的素材边界——
浏览器只能把源矩形按比例裁掉一截，字形被横向拉宽了 1.5%，标注线也整体偏。

**对策**：几何常量从 `web/img/<素材>/meta.json` 的 `cell` 字段抄，不要自己算。
`check_crop.py` 会拿镜头代码里的 `CH/TOP/COLW/PADX` 和 `meta.json` 逐个比对。

## 3. 换字体、换列数、换输出宽度，都会改网格

**症状**：重录素材后标注层整体偏移。

**原因**：列宽来自字体的真实 advance 和内边距，跟 `font` / `cols` / `out_width` /
`scale` 绑死。任何一个变了，网格就变了。

**对策**：重录 = 重抄 `meta.json` 的四个数。把这步写进流程，别靠记。

## 4. profile 和镜头代码各有一张裁剪表

**症状**：改了 profile 的裁剪范围，画面没变；改了镜头代码的，profile 的自检报错。

**原因**：profile 声明「每种画幅取哪几行几列」，镜头代码的 `CARD` 表实现它。
改了一处忘了另一处，裁剪范围就悄悄变了。

**对策**：`check_crop.py` 双向对照。两边都改，改完再跑。

## 5. 一个镜头里换裁剪范围，卡片在切点处变形

**症状**：两张卡片叠化时突然变窄/变宽。

**原因**：卡片尺寸由裁剪区域决定。S01 和 S02 是连续播放同一张终端卡，
S02 换了裁剪范围，切过去的一瞬间尺寸就变了。

**对策**：连续播放同一素材的镜头用同一套裁剪。不同画幅之间用不同裁剪没问题——
画幅本来就是分开渲染的。

## 6. 竖版和方版的标注层不能压在终端卡上

**症状**：编号徽章盖住了终端里的字。

**原因**：竖版/方版的终端卡是满宽的，卡里没有留白可放标注。

**对策**：横版把徽章排在卡片右侧；竖版和方版排在卡片**下面**。
方版高度不够放不下两行说明，就只留命令名——物理上放不下就别硬塞。

## 7. 真实命令的节奏是零

**症状**：终端里的命令瞬间刷完，画面像卡住。

**原因**：真实命令几十毫秒就跑完了，终端里是「瞬间刷完」。

**对策**：时间轴不采自真实耗时，由脚本按「打字速度 + 逐行打印 + 停顿」合成。
内容是真的（命令真跑、输出原样采集），节奏是编排的。

## 8. 静帧会随机冻住一个光标

**症状**：两张静态卡片上有个莫名其妙的小方块。

**原因**：录制时光标在闪（每 5 帧换一次状态），末帧落在哪一帧取决于总帧数。

**对策**：静帧重画一遍，不画光标。录制器现在固定这么处理。

## 9. docmd 改写 markdown 链接，但不改 `<video>` 的 src

**症状**：视频在本地能播，部署到 GitHub Pages 后 404。

**原因**：docmd 会把 markdown 里的相对链接改成带子路径的形式，但 `<video src="...">`
是 HTML 原样透传的。

**对策**：`<video>` 的 src 按页面深度**手写**（`../assets/video/x.mp4` 还是
`../../assets/video/x.mp4`），改完在本地 http server 上按 Pages 子路径模拟一遍再部署。

## 10. 只用作静态卡片的素材也在产出几十 MB 序列帧

**症状**：`web/img/` 底下多出 `repo/`、`skill/` 两个目录，各 20~30MB。

**原因**：录制器默认既出序列帧又出静帧，但这类素材在画面上只用到静帧。

**对策**：profile 的 `capture.seq: false` 只出静帧。序列帧目录已 gitignore。

## 11. 重录素材后忘了同步 `web/project.js`

**症状**：渲染一启动就报「图片解码失败：img/version/0039.png」，页面白屏。

**原因**：`web/project.js` 里的序列帧清单是 `tools/timeline.py` 扫描 `web/img/*/` 得来的，
是一份**快照**。重录素材后帧数变了（比如从 39 帧变成 37 帧），清单还指着旧帧号，
页面按旧清单去加载已经不存在的图片。

**对策**：重录素材后必须重跑 `tools/timeline.py`。流水线的 `sync` 步骤做的就是这件事，
它排在 `record` 之后、`render` 之前，别跳过。

这一步会按配音重新对齐时间线，所以配音产物（`audio/narration.wav`）必须在；
不在的话它会失败而不是默默改时间线——这是故意的。

## 12. 事实清单写「本机有几个技能」这种会过期的事实

**症状**：片子发出去两周，环境变了，画面上的数字就错了。

**原因**：这类数字随本机状态变，既不能核也不该上画面。

**对策**：核不了又确实想讲的，用 `manual` 并写清为什么核不了；
会过期的干脆不写。「内容必须真实」不等于「能写多少写多少」。
